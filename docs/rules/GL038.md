# GL038 — Hardcoded credential literal in script line

**Severity:** `error`  
**OWASP:** [CICD-SEC-6 – Insufficient Credential Hygiene](https://owasp.org/www-project-top-10-ci-cd-security-risks/CICD-SEC-06-Insufficient-Credential-Hygiene)

## What glsec checks

glsec flags script lines that pass a literal (non-variable) credential to a known CLI tool via a flag or environment variable:

| Tool | Detected pattern |
|------|-----------------|
| sqlcmd | `-P <literal>` |
| mysql / mysqldump / mysqlpump | `-p<literal>` or `--password=<literal>` |
| psql | `PGPASSWORD=<literal>` |
| mongosh / mongodump / mongorestore | `--password <literal>` |
| docker login / podman login | `-p <literal>`, `--password <literal>`, `--password=<literal>` |
| sed | URL rewrite `s/user:[^@]*@/user:<literal>@/` |

A value is considered hardcoded when it does not begin with `$` (i.e. is not a CI variable reference).

No finding is reported when the credential only reaches the job's own
service container: the database exists only for this job,
so a reader of the file cannot reach it. That means a database command whose
host option (`-h`, `--host`, `-S`, `PGHOST`) names a service alias of the
same job, or a service image hostname, is not flagged. A service image
hostname is derived from the whole image name with the tag stripped and
every `/` replaced by `__` or `-` (for example,
`registry.example.com/team/mysql` is reachable as
`registry.example.com__team__mysql` and
`registry.example.com-team-mysql`); only an image without a slash, like
`mysql:8.0`, is reachable under its bare name. The loopback hosts
`localhost`, `127.0.0.1`, and `::1` are suppressed only when the job has
services (its own, inherited, or from `default:`): on a shell executor,
common on self-hosted runners, localhost is the runner machine, so a
credential to localhost in a job without services is a real finding.
A credential with no host option, or one that also reaches an
external host, is still flagged, as are `docker login` and `sed` findings,
which have no service target.

## Trigger example

```yaml
restore-db:
  script:
    - sqlcmd -S db.example.com -U SA -P "ExampleP4ss!" -Q "RESTORE DATABASE [app] FROM DISK = '/backup/app.bak'"
    - sed -i "s/sa:[^@]*@/sa:ExampleP4ss!@/" .env
```

## Safe alternative

```yaml
restore-db:
  script:
    - sqlcmd -S db.example.com -U SA -P "$MSSQL_SA_PASSWORD" -Q "RESTORE DATABASE [app] FROM DISK = '/backup/app.bak'"
    - sed -i "s/sa:[^@]*@/sa:${MSSQL_SA_PASSWORD}@/" .env
```

A literal password for the job's own service container is also not flagged:

```yaml
integration:mysql:
  services:
    - name: mysql:8.0
      alias: mysql
  script:
    - mysqladmin ping -h mysql -uroot -pci-only --silent
```

Store the password as a masked, protected CI/CD variable in GitLab project or group settings.
